# verbacue GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a desktop GUI (`verbacue-gui`, iced) that the `verbacue` binary opens with `verbacue gui` or with no arguments, and that matches the approved mockups.

**Architecture:** The video pipeline moves from the CLI into the facade (`verbacue::pipeline`), so the CLI and the GUI run the same code. The core `Progress` trait gets cancel and live-cue support. `verbacue-gui` is a library with one entry point (`run()`); the renamed `verbacue-app` crate calls it behind the default feature `gui`.

**Tech Stack:** Rust 2024, iced 0.14 (features `tokio`, `canvas`, `image`, `svg`, `advanced`), tokio 1, thiserror 2, rfd (async file dialogs), serde + toml (settings).

**Spec:** `docs/superpowers/specs/2026-11-08-gui-design.md`. Mockups: `docs/superpowers/specs/gui-mockups/*.dc.html` (the visual specification; copy layout, sizes, copy and timings from their inline styles).

## Global Constraints

- New dependencies: a version at least 2 weeks old on the day it is added (rfd 0.18.0 is from 2026-11-07, so use 0.17.x until 2026-11-21).
- Dependencies in strict alphabetical order in each `Cargo.toml`; table format `x = { version = "…" }`.
- Workspace lint `unsafe_code = "deny"`; only `hwdecode.rs` and the new Windows console module may `#![allow(unsafe_code)]`.
- No `println!` in library code; logging with `tracing`.
- Comments and user-facing text: simplified technical English (ASD-STE100), few comments.
- Commits: `<type>(<scope>): <subject>` in the past tense, no AI attribution lines, secret scan of the staged diff before each commit, push to `feature/gui`.
- `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass after every task.
- Colors, fonts and animation timings: exactly as in the spec's "Look and animation" section and the mockups.
- Linux CPU binaries stay fully static (no GUI); all other release binaries include the GUI.

## Review Focus

1. A video path with spaces or non-ASCII letters (`Szép film.mkv`): every screen and every output file name must work. Test in Task 5 and Task 9.
2. A `gui.toml` from another version, with unknown or missing keys: missing keys take defaults, unknown keys are ignored, no "broken file" notice. Test in Task 8.
3. A dropped file that is not a video, or a video without audio: a short error on the drop zone, no crash, stay on Pick a video. Test in Task 9.
4. The window closes during a conversion: the pipeline cancels and removes its partial output. Test in Task 3 (partial file removed) and Task 11 (close request sends cancel).
5. An online translator without a key, or an output folder that cannot be written: a friendly error card on the Converting screen, not a panic. Test in Task 11.

  ```rust
  pub struct Job {
      pub video: PathBuf,
      pub audio_track: usize,
      pub whisper_model: String,       // a known name or a path
      pub vad: bool,
      pub language: Option<String>,    // None = detect
      pub translation: Option<Translation>,
      pub format: subtitle::Format,

      pub burn: bool,                  // needs feature "video"
      pub force: bool,
  }
  pub struct Translation {
      pub backend: translate::Backend, pub target: String, pub register: translate::Register,
      pub glossary: Option<PathBuf>, pub llm_model: String,
      pub endpoint: String, pub endpoint_model: Option<String>,
  }
  pub enum Step { Download(&'static str), Decode, Transcribe, Translate, Embed, Burn, Save }
  pub enum Event<'a> { Step(Step), Progress { done: u64, total: u64 }, Cue(&'a Cue), Wrote(&'a Path), Skipped(&'a Path), Note(&'a str) }
  pub trait Sink: Sync { fn event(&self, event: Event<'_>); fn cancelled(&self) -> bool { false } }
  pub struct Outcome { pub source_language: String, pub files: Vec<PathBuf>, pub skipped: bool }
  pub struct Pipeline { /* the translator, loaded on first use and kept */ }
  impl Pipeline {
      pub fn new() -> Self;
      pub fn run(&mut self, job: &Job, sink: &dyn Sink) -> Result<Outcome>;
  }
  pub fn final_output(job: &Job) -> Option<PathBuf>;   // the file that marks the job as done
  pub fn output_path(job: &Job, lang: &str) -> PathBuf;
  ```
