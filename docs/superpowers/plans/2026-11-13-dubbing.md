# Dubbing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** verbacue writes an MKV with a new audio track. The track speaks the translated subtitles in the cloned voices of the actors.

**Architecture:** A new crate, `verbacue-dub`, runs XTTS-v2 and HTDemucs as ONNX graphs with `ort`. `verbacue-media` decodes the audio and writes the MKV with the FFmpeg that is already in the binary. The `verbacue` pipeline gets an optional dub step, and the command line and the desktop app set it.

**Tech Stack:** Rust 2024, `ort` 2.0.0-rc.15 (static ONNX Runtime), the existing static FFmpeg (`ffmpeg-next` 9), egui for the app. For developers only: Python 3.11 with `uv`, `coqui-tts` (idiap fork), `demucs-onnx`, `onnxruntime`.

**Spec:** `docs/superpowers/specs/2026-11-13-dubbing-design.md`

## Global Constraints

- No GPL code in the binary. No Python at run time.
- Every model file is downloaded on first use and checked with SHA256 (`verbacue-core/src/models.rs`).
- XTTS-v2 licence: non-commercial (CPML). The user accepts it before the first download.
- The voice speaks the target language of the translation (`--to`). There is no separate voice language.
- XTTS-v2 languages: `en es fr de it pt pl tr ru nl cs ar zh-cn ja hu ko hi`. Any other target refuses the dub before the transcription starts.
- Speed limit: default 1.3, range 1.0 to 1.5. Worst case 1.5, with a warning.
- Output: `<name>.<lang>.dub.mkv`. It holds all original streams, the new AAC stereo track (default track, title `<Language> (AI voice)`), and the subtitles as soft tracks.
- Defaults: `--dub-voice clone`, `--dub-original remove`, `--dub-speed-limit 1.3`, `--dub-model` = `xtts-v2` in a CUDA build, else `xtts-v2-int8` (about twice as fast on a CPU, also on Apple Silicon).
- `unsafe_code = "deny"` stays on. All new crates use `[lints] workspace = true`.
- Comments and docs follow the house style: short, plain, Simplified Technical English.
- One PR from `feature/dubbing`. Each task is one commit. Each commit builds and passes `cargo test --workspace`.
- Tests that need the real models are `#[ignore]` and run with `cargo test -- --ignored` on a developer machine.

## Review Focus

1. **A translated line that is longer than the XTTS-v2 text limit** (224 characters for Hungarian, 250 for most others). The app must split it at sentence ends and join the audio, not cut it. The test is in Task 2.3.
2. **Lines with no speech** (`[music]`, `♪ ... ♪`, `...`, empty after cleaning). They must stay silent and must not reach the GPT. The test is in Task 2.2.
3. **Cues that overlap, touch, or have `end <= start`.** The time fit must never let one line play over the next one. The test is in Task 3.1.
4. **A video without audio, or `--audio-track` out of range.** The app must stop with a clear error before it downloads 2 GB of models. The test is in Task 3.4.
5. **Cancel during "Speaking line N of M".** The app must stop within one line, delete the temporary files, and leave no file with the final output name. The test is in Task 3.4.

**Files:**

**Interfaces:**
- Produces (the files that Step 2 reads, in one folder; see `tools/xtts-export/README.md`):
  - `conditioning.onnx`: in `mel` `[1, 80, T]` (22.05 kHz mel, made in Rust) → out `cond_latents` `[1, 32, 1024]`
  - `speaker.onnx`: in `mel` `[1, 64, T]` (16 kHz mel with pre-emphasis, made in Rust) → out `speaker_emb` `[1, 512, 1]`
  - `gpt.onnx`: in `embeds` `[1, T, 1024]`, `past_k_<i>`/`past_v_<i>` `[1, 16, P, 64]` for i in 0..30 (P = 0 for the first pass) → out `logits` `[1, 1026]` (last position), `latents` `[1, T, 1024]`, `present_k_<i>`/`present_v_<i>`
  - `gpt_int8.onnx`: `gpt.onnx` with per-channel INT8 weights
  - `vocoder.onnx`: in `latents` `[1, T, 1024]`, `speaker_emb` `[1,512,1]` → out `wav` `[1, N]` (24 kHz)
  - `embeddings.safetensors`: `text_embedding`, `text_pos_embedding`, `mel_embedding`, `mel_pos_embedding`. Rust adds them up: the first pass is `[cond_latents; text_emb[start, ids.., stop] + text_pos[0..]; mel_emb[start] + mel_pos[0]]`, and step n is `mel_emb[code] + mel_pos[n]`.
  - `speakers.safetensors`: the studio voices, keys `<name>.cond_latents` `[32,1024]` and `<name>.speaker_emb` `[512]`
  - `vocab.json`: the XTTS-v2 BPE tokenizer file, unchanged
  - `config.json`: token ids, `char_limits`, `cond_mel`, `speaker_mel` and `sampling` settings
  - `fixtures/tokens.json`: 20 sentences and their token ids from the Python tokenizer. `parity.py` holds the numpy reference of the mel code and of the generation loop (the HF repetition penalty also covers token 1 and the start code).

## Step 3: Time fit, mix, the new track and the command line

### Task 3.1: Time fit

**Files:**
- Create: `crates/verbacue-dub/src/fit.rs`

**Interfaces:**
- `pub struct Slot { pub cue: usize, pub start_ms: u64, pub end_ms: u64, pub next_start_ms: Option<u64> }`. `cue` is the index of the cue in the input, because `slots` sorts.
- `pub fn slots(cues: &[Cue]) -> Vec<Slot>`: it sorts by start. It sets `end_ms = max(end_ms, start_ms + 200)`. It clamps `end_ms` to the next cue's start. Cues with the same start get starts 1 ms apart, so `end_ms > start_ms` always holds.
- `pub struct Fit { pub factor: f32, pub warn: bool }`
- `pub fn fit(natural_ms: u64, slot: &Slot, limit: f32) -> Fit`, with these rules:
  1. If the line fits the slot at factor 1.0, the factor is 1.0.
  2. Otherwise it uses a factor up to `limit` to fit `end_ms`.
  3. If the line still does not fit, it fits the line into `next_start_ms - 100` (or `+∞`) at a factor up to `limit`.
  4. If the line still does not fit, it uses a factor up to 1.5 with `warn = true`.
  5. Above 1.5, the factor is 1.5 with `warn = true`. The mixer then cuts the line at `next_start_ms` with a 30 ms fade.
  `factor` is the speed (1.3 = 30 % faster). The latents get `stretch(1.0 / factor)`.

- [x] **Step 1: Write the failing tests.**
  - `fits_without_change`: 1000 ms in a 1500 ms slot gives `factor == 1.0`.
  - `speeds_up_to_limit`: 1300 ms in a 1000 ms slot with limit 1.3 gives `factor == 1.3` and `!warn`.
  - `uses_the_gap`: 2000 ms in a 1000 ms slot, next start at +3000 ms, gives `factor == 1.0`.
  - `warns_above_limit`: 2000 ms, slot 1000 ms, next start at +1100 ms, limit 1.3, gives `factor == 1.5` and `warn`.
  - `slots_never_overlap`: overlapping, touching and `end <= start` cues give slots with `end_ms <= next.start_ms` and `end_ms > start_ms`.
